위 수치는 UI 렌더링 및 DB 조회를 제외한 엔진 측정입니다. 최초 분석은 애플리케이션 캐시가 비어 있는 상태이지만 OS 디스크 캐시는 비우지 않았습니다. 각 측정은 한 번의 관측값이며 Windows 회사 PC나 실제 로그의 분포에 대한 보장값이 아닙니다. 블록 색인은 흔한 키워드에서 많은 블록을 읽을 수 있으며, 이번 샘플의 `S6F11`은 약 472MiB를 읽었습니다. 그럼에도 블록 읽기·문자열 검사·결과 구성 전체를 위 시간 안에 수행했습니다.

정확성 검증:

- C# 자동 검증 2,071개 통과(preview.2 로컬 검증): 순차/병렬 원문·메시지 일치, CRLF/마지막 개행 없음, INI 제외, 색인·캐시 재사용/무효화, 단문·Unicode·정규식·AND/OR/제외/북마크·시간 조건, 취소, DB 지연 조회/실패, 분석 후 원본 변경 시 상세/복사 거부, 활성 캐시 격리 후 기존 세션 조회 유지·복구 캐시 재사용.
- 기존 Python 회귀 테스트 106개 통과. 최종 C# Release 빌드 오류 0개, 경고 0개.
- 기존 Python과 10만 건 전체의 시간·종류·파일·라인 번호·정규화 메시지 SHA-256 일치: `77a987732fe3dec54f66c15f83d3cd960f8c1a6d7a331be5a1de528dac22f5e4`.
- 날짜가 겹치는 다중 날짜 샘플 16건도 전체 결과 해시 일치.
- 실제 Avalonia 창의 파일 분석, 조건 편집 시 미적용, 적용 결과, 다른 페이지의 좌우 선택 연동, 상세 표시, F3/F4 로직, 독립 컬럼 설정 자동 점검 통과.
- 최종 컬럼 폭·버전 정리 후 화면 재실행은 macOS 네이티브 RenderTimer 오류 `-6661`로 시작 전 중단됨. 디스플레이가 비활성화된 환경에서 보고된 [Avalonia 문제](https://github.com/AvaloniaUI/Avalonia/issues/18895)와 동일한 오류이며, 화면을 켠 상태의 최종 재검증은 남아 있음. 앞선 GUI 검증 통과와 구분한다.
- 실제 회사 SQL Server 연결은 접근 가능한 서버가 없어 미검증. 기존 스키마 기반 조회 코드와 모의 DB로 대상 ID 제한·재사용·실패 동작 검증.
